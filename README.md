# 쇼더스 대본 품질 판정기

쇼더스(ShortUs)가 만든 쇼츠 대본을 영상으로 만들기 전에 **통과 · 보류 · 탈락**으로 판정합니다. 어느 장면의 어느 문장이 왜 걸렸는지 함께 알려 줍니다. 음성으로 읽을 때 틀리기 쉬운 표기를 바꿔 **고친 대본**을 냅니다. 보류·탈락이면 걸린 곳만 고쳐 **다시 판정**하고 영상에 쓸 대본을 정합니다.

- **써 보기: https://shortus-judge.sync-block.app** (한국에서만 판정을 받습니다)
- 기준표: [data/labels/rubric.md](data/labels/rubric.md)
- 작업하며 내린 결정과 쓴 시간: [DECISIONS.md](DECISIONS.md) (D1~D40). 아래 D 번호는 이 문서에서 찾을 수 있습니다.

## 실행

python 3.11 이상만 있으면 됩니다(추가 패키지 없음). 모델은 로그인한 Claude Code(`claude` 명령, 기본)로 부르거나, `.env`에 `ANTHROPIC_API_KEY`를 넣고 `JUDGE_BACKEND=api`로 부릅니다.

```sh
./judge.sh web                                   # 화면 → http://127.0.0.1:8787 (다른 포트: ./judge.sh web 8799)
./judge.sh one data/scripts/product-01-g1.json   # 대본 하나 판정
./judge.sh test                                  # 시험용 50개를 새로 판정하고 정답과 견줌(약 4분, 약 800원)
python3 tools/evaluate.py results/v5-test --set test --redecide   # 아래 결과 표의 숫자를 저장한 결과로 다시 냄(모델 호출 없음)
python3 -m unittest discover tests               # 모델을 부르지 않는 테스트
```

- **화면에서 판정하는 두 가지 방법**
  - 「쇼더스로 대본 만들기」: 원래 글을 넣으면 쇼더스가 만든 대본을 판정합니다(`.env`에 `SHORTUS_API_KEY` 필요).
  - 「가진 대본 넣기」: 넣은 대본을 판정합니다.
- **걸리는 시간과 비용:** 판정 한 번에 약 20~40초, 약 15원입니다. 고친 뒤 다시 판정하면 약 1분, 약 30원입니다.
- **명령으로 받는 결과:** `python3 -m judge <대본> --json`을 쓰면 근거 문장, 고친 대본, 다시 판정한 결과를 JSON으로 받습니다.

## 1. 좋은 대본의 기준

영상은 대본대로 렌더링되므로, 대본만 보고 판단할 기준을 10개 정했습니다.

| 묶음 | 기준 | 걸리면 |
|---|---|---|
| 사실 | 1 넣은 글에 없는 내용·바뀐 뜻이 없다 · 2 숫자·날짜·이름이 같다 | **탈락** |
| 사실 | 3 넣은 글보다 세게 말하지 않았다 · 4 꼭 있어야 할 내용이 빠지지 않았다 | 보류 |
| 듣기 | 5 목소리가 잘못 읽는 표기가 없다 | 고친 대본을 냄. 못 고치면 보류 |
| 듣기·구성 | 6 말하듯 쓴 문장 · 8 첫 장면 · 9 되풀이 없음 | 2개 이상이면 보류 |
| 듣기·구성 | 7 길이 · 10 끝맺음 | 진단만 |

- **틀린 내용이 가장 나쁩니다.** 시청자는 원문과 맞춰 보지 않습니다. 가장 흔한 오류는 조건이 빠져 숫자가 다른 대상에 붙는 것이었습니다. 예를 들어 「컵라면 하나 분량의 물을 4분」이 「4분이면 물이 끓고」로 바뀌었습니다(D8). 다만 애매한 것은 탈락시키지 않습니다(D15, D21).
- **목소리가 잘못 읽는 숫자는 한글로 풀어 씁니다.** 쇼더스 목소리는 같은 문장도 매번 다르게 읽습니다. 숫자로 쓴 문장은 28번 중 10번 틀렸고, 한글로 풀어 쓴 문장은 모두 맞았습니다. 고친 대본의 숫자 장면 211개 중 1개만 다르게 들렸습니다(D27, D28).
- **판단이 갈리는 항목 하나로는 보류하지 않습니다.** 말투·첫 장면·되풀이가 그렇습니다. 길이는 렌더링에서 맞출 수 있어 진단만 합니다.

## 2. 판정 방식

```
대본 + 넣은 글
 ├─ 코드  기준 5(표기 → 고친 대본), 기준 7(길이)
 ├─ 모델  사실 묶음(기준 1~4) — 3번 따로 물어 과반
 └─ 모델  구성 묶음(기준 6·8·9·10) — 1번
      ↓ 기준마다 걸림 여부 + 장면·인용·근거
 판정 선(코드) → 통과 · 보류 · 탈락
      ↓ 보류·탈락이면
 걸린 곳만 모델이 고침 → 코드가 숫자를 대조해 잘못 고친 장면을 되돌림 → 다시 판정(한 번)
```

| 고른 것 | 버린 것 | 까닭 |
|---|---|---|
| 기준별 걸림 + 코드가 판정 | 모델이 점수를 매김 | 점수는 어디를 고칠지 알려 주지 않고 흔들립니다. 판정 선을 바꿀 때 모델을 다시 부르지 않아도 됩니다 |
| 통과·보류·탈락 세 단계 | 두 단계 | 「틀리지 않았지만 고칠 것」은 사람이 보도록 남깁니다 |
| 하이쿠 + 세 번 물어 과반 | 소넷 + 세 번 물어 과반 | 비용은 1/9이고 일치한 수는 1~2개 차이 납니다. 한 번만 물으면 탈락 기준이 흔들렸습니다(D9, D11, D12) |
| 고친 대본도 같은 판정 선을 통과해야 영상으로 만듦 | 끝까지 못 고친 대본도 만듦 | 보류는 계속 사람이 봅니다(D35) |

모델 답을 못 받은 기준이 하나라도 있으면 통과시키지 않습니다.

## 3. 확인한 방법과 결과

- **정답:** 시청자 유형이 다른 채점 에이전트 세 명이 대본 98개를 따로 매기고, 기준마다 다수결을 정답으로 씁니다. 채점자들이 탈락으로 합의한 대본은 모두 제가 원문과 대조했습니다(D3, D4).
- **개발용·시험용 구분:** 개발용 48개로만 지시문을 고쳤습니다. 시험용 50개는 정답을 확정한 뒤 결과를 한 번만 열었습니다(D19, D26).

| 시험용(처음 보는 대본 50개) | 값 |
|---|---|
| 일치 | **24/50** (48%, 95% 구간 35~61%) · 모두 보류로 냈을 때 20 |
| 잘못 통과 (정답이 탈락인 13개 중) | **2개** — 나머지 11개는 통과시키지 않음 |
| 잘못 탈락 (정답이 통과·보류인 37개 중) | 6개 |

11-24에 같은 판정기로 다시 시험하니 일치 31/50, 잘못 통과 2개, 잘못 탈락 4개가 나왔습니다. 모델 답이 실행마다 달라 일치 수는 7개까지 차이 났고, 잘못 통과한 2개는 두 번 모두 같은 대본이었습니다. 표에는 처음 잰 값을 담았습니다.

**읽는 법:** 전체 일치는 기준선보다 조금 나을 뿐입니다. 대신 치명 오류가 있는 대본은 대체로 걸러냅니다. 이 판정기는 보류를 많이 내는 대신 치명 오류를 적게 놓칩니다. 6·7판은 보류를 줄였지만 치명 오류를 더 많이 놓쳐 기본으로 쓰지 않았습니다(D30, D32). 개발용에서 보류·탈락한 12개 중 11개는 한 번 고친 뒤 다시 판정했을 때 통과했습니다(D35).

## 4. 한계

- **정답의 한계:** 정답도 모델(채점 에이전트)이 만든 것이고, 사람이 확인한 것은 탈락 합의뿐입니다. 채점이 얼마나 일치하는지도 기준별로 κ 0.59~0.76입니다(98개).
- **두 번째 정답 기준:** 채점자가 「애매」로 적은 걸림을 빼면 98개 중 56개를 맞혀, 모두 통과로 냈을 때(58개)보다 적습니다. 판정기가 애매한 것까지 보류해 보류가 많기 때문입니다(D29).
- **대본 수:** 대본이 98개뿐이라 시험 결과의 95% 구간 폭이 26%p나 됩니다.
- **기준 4(빠진 내용):** 처음 보는 글에서 빠진 내용을 놓칩니다(합의 21개 중 14개).
- **고친 대본의 평가:** 고친 대본도 같은 판정기로 채점했습니다. 따로 정답을 매기지는 않았습니다.
- **쇼더스로 다시 넣기:** 고친 대본을 쇼더스에 다시 넣는 부분은 만들지 않았습니다.
